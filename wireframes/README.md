**Learning objective:** By the end of this lesson, students will be able to create one wireframe showing their game’s main screen.

## Give your stories a place on the screen

Our stories describe what players need to do. We now need to decide where they will do it.

A **wireframe** is a simple sketch of a screen. It shows the main content, controls, and layout.

Use boxes and labels. You do not need final colors, fonts, or images.

## Sketch a game screen together

For our memory matching example, we need space for:

| Screen area | Purpose |
| ----------- | ------- |
| Game title | Identify the game |
| Instructions | Explain how to play |
| Moves remaining | Show progress |
| Card grid | Let the player select cards |
| Message area | Show feedback and the final result |
| Play Again button | Start another round |

In Excalidraw:

1. Draw a large rectangle for the page.
2. Add the game title near the top.
3. Draw a box for the instructions.
4. Add smaller rectangles for the cards.
5. Add labels for the moves counter and message area.
6. Draw and label the **Play Again** button.

A label such as `Result message appears here` is enough to show where changing content belongs.

## 🎓 You Do: Create one wireframe

Create **one wireframe of your game’s main screen** in Excalidraw.

Include:

- Your game’s name.
- Instructions, or a clearly labeled control that opens them.
- The main game area.
- The buttons or controls the player needs.
- Space for feedback and the game result.
- Any score, turn, timer, or move information your game requires.

Check that your main MVP stories have a clear place on the screen.

## Save your work

Use Excalidraw’s menu to:

1. **Save to file** to keep an editable `.excalidraw` copy.
2. Use **Export image** to save a PNG named `wireframe.png`. [GitHub](https://github.com/excalidraw/excalidraw/blob/master/packages/excalidraw/locales/en.json)

Keep both files. We will add the PNG to your repository during the final check.
