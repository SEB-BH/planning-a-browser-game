**Learning objective:** By the end of this lesson, students will be able to create a GitHub Projects board with four workflow columns.

## Make the work visible

A **kanban board** displays work as cards arranged in columns.

Each card represents a piece of work. Its column shows its current status.

We will use these four columns:

| Column | What belongs here |
| ------ | ----------------- |
| **Product Backlog** | Planned work we have not selected for the current sprint |
| **Sprint** | Work selected for this sprint that we have not started |
| **Doing** | Work we are currently completing |
| **Done** | Work we have finished and tested |

The **product backlog** is the ordered list of work for the product. On our simple board, its column holds work waiting to be selected.

## Create the project

Follow along with the instructor:

1. Open your GitHub **profile**.
2. Select **Projects**, then **New project**.
3. Choose **Board** under **Start from scratch**.
4. Name it after your game, such as `Landmark Match — Project Plan`.
5. Select **Create project**. [GitHub Docs](https://docs.github.com/en/issues/planning-and-tracking-with-projects/creating-projects/creating-a-project)

## Set up the columns

1. Open the project’s top-right menu and select **Settings**.
2. Select the **Status** field.
3. Edit the existing options and add an option so you have:
   - `Product Backlog`
   - `Sprint`
   - `Doing`
   - `Done`
4. Save your changes.
5. Return to the board and arrange the columns in that order.

The board should use **Status** for its columns. If a column is hidden, use the add-column control on the right to show it. [GitHub Docs](https://docs.github.com/en/issues/planning-and-tracking-with-projects/understanding-fields/about-single-select-fields)

## Connect the board to your repository

GitHub Projects belong to an account or organization. We link our project to the repository so we can find it from the repository’s **Projects** tab.

1. Open your game’s repository.
2. Select **Projects**.
3. Select **Link a project**.
4. Search for your new project and select it. [GitHub Docs](https://docs.github.com/en/issues/planning-and-tracking-with-projects/managing-your-project/adding-your-project-to-a-repository)

In the project’s **Settings**, set its visibility to **Public** so your instructors can view your planning. The board’s visibility is separate from the repository’s visibility. [GitHub Docs](https://docs.github.com/en/issues/planning-and-tracking-with-projects/managing-your-project/managing-visibility-of-your-projects)
